# Task 2 — Росстат / ОКТМО

## Цель

Закрыть production-ingestion официального открытого набора ОКТМО
Росстата для последующей территориальной привязки данных «Земля Радар».
Первый прикладной фильтр — Калужская область.

## Команда запуска

Из корня репозитория:

    python -m landradar.source_cli rosstat-health --raw-dir data/raw/task02

Затем рабочая загрузка:

    python -m landradar.source_cli rosstat-oktmo \
      --raw-dir data/raw/task02 \
      --output data/normalized/rosstat_oktmo_kaluga.json

Для Windows PowerShell использовать одну строку без обратного слеша.

## Этапы

1. Выполнить live-healthcheck паспорта и CSV Росстата.
2. Сохранить raw snapshots паспорта и CSV с SHA-256.
3. Определить актуальный data-*.csv из паспорта, без зашитой даты.
4. Распарсить CSV с определением кодировки и разделителя.
5. Проверить непустой набор и наличие полей заголовка.
6. Выделить строки, относящиеся к Калужской области.
7. Сохранить нормализованный JSON с dataset_id, URL, snapshots и фильтром.
8. Выполнить повторный live-run и сравнить provenance/структуру.
9. Проверить failure-сценарий: ошибка нового ответа не затирает старые snapshots.
10. Зафиксировать ограничения лицензии и дату получения.
## Критерии приёмки

- паспорт Росстата отвечает HTTP 200;
- ссылка на актуальный CSV разрешается автоматически;
- CSV реально скачан и сохранён как immutable raw snapshot;
- SHA-256 паспорта и CSV присутствуют в provenance;
- парсер обрабатывает реальную кодировку и разделитель;
- набор непустой;
- найдено минимум одно совпадение по Калужской области;
- нормализованный JSON валиден и содержит dataset_id, data_url,
  snapshots, filter и records;
- повторный live-run проходит без повреждения предыдущего результата;
- ошибка HTTP/схемы оставляет предыдущие рабочие snapshots неизменными;
- ограничения использования официального набора записаны в provenance;
- локальные тесты и live-check проходят.

## Файлы результата

- data/raw/task02/ — паспорт и CSV snapshots;
- data/normalized/rosstat_oktmo_kaluga.json — отфильтрованный результат;
- docs/TASK_02_EVIDENCE.md — evidence после успешного gate;
- CHANGELOG.md и README.md — статус блока после приёмки.

## Автономный порядок работы

После завершения Task 1 проверить clean/dirty состояние,
запустить команды выше, выполнить повторный запуск и тесты,
затем записать evidence и сделать commit в Git. Публикацию в GitHub
выполнять только после успешных локальных проверок.
