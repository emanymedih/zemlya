# Правила разработки

1. Проект развивается ключевыми блоками.
2. Следующий блок не начинается до закрытия текущего.
3. Исключение: найден более эффективный рабочий способ решить ту же задачу; замена должна быть обоснована и проверена.
4. Каждый источник проходит факт-чек, локальные тесты, live-check и повторную проверку.
5. Отсутствующие данные остаются отсутствующими.
6. Любой рабочий факт обязан иметь provenance.
7. Цена предложения, кадастровая стоимость, цена торгов и цена зарегистрированной сделки являются разными типами данных.
8. Расчёт или производный факт обязан хранить исходные значения и метод получения.
9. Неподтверждённая гипотеза не выдаётся за факт.
10. Архитектурное решение принимается с учётом полного конвейера проекта, чтобы блок оставался полезным для следующих стадий.

## Критерий DONE для источника

- контракт/схема проверены;
- реальный ответ получен;
- raw snapshot сохранён;
- хэш сохранён;
- парсер обработал реальный ответ;
- повторный live-run прошёл;
- ограничения использования/лицензии зафиксированы;
- failure-сценарий не портит предыдущие рабочие данные.
