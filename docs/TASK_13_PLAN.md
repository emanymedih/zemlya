# Task 13 — официальный источник кадастровых участков

Статус: **PLANNED**. Следующий блок ядра после закрытия Tasks 5–12.

## Цель

Получать по кадастровому номеру документированные сведения об участке из
официального машинно-доступного источника, хранить снимки и обнаруживать
изменения между полученными версиями. Использовать общий конвейер
raw → normalized → entity → relations и сущность ParcelRecord.

## Обязательная разведка до реализации

1. Подтвердить доступный официальный канал НСПД/Росреестра для поиска участка.
2. Проверить разрешённый режим автоматизированных запросов, аутентификацию,
   лимиты, стоимость, лицензирование и доступность для нашего контура.
3. Зафиксировать фактический состав ответа, формат, временные поля и смысл дат.
4. Разделить публичные атрибуты, официальные выписки и ограниченные сведения.
5. Установить поведение источника при отсутствии объекта, изменении схемы,
   недоступности сервиса и устаревшем ответе.

## Минимальный объём реализации

- Запрос по кадастровому номеру через разрешённый официальный канал.
- Неизменяемое сохранение исходного ответа, URL/идентификатора запроса,
  fetched_at, source effective/updated time (если источник их сообщает),
  HTTP/документного статуса, hash, схемы и версии кода.
- Нормализация только присутствующих значений с provenance на каждый факт.
- Сохранение версий снимков и отчёт diff с полем, старым/новым значением,
  временем получения и ссылками на оба доказательства.
- Отдельные статусы: current_at_source, retrieved_at, stale, unknown, failed.
- Ограничение темпа запросов, кэширование и корректная обработка ошибок.
- Защита персональных/ограниченных данных; сбор только в пределах законного
  доступа и подтверждённых условий использования.

## Границы и критерии приёмки

- Не обещать поток уведомлений о каждой регистрационной операции, пока такой
  официальный канал и право его использования не подтверждены.
- При отсутствии ленты событий обнаруживать изменения сравнением повторных
  официальных снимков; хранить точные даты и ограничения метода.
- Отделять реестровую геометрию от OSM и не трактовать близость дороги как
  юридический доступ к участку.
- Fixture tests, Docker suite, официальный live-check по тестовым кадастровым
  номерам, повторный запрос и сохранённый отчёт качества/provenance.
- До подтверждения интерфейса и правил доступа реализация остаётся PLANNED.
