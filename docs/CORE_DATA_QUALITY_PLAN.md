# План повышения качества данных ядра

## Назначение

План усиливает достоверность, свежесть, воспроизводимость и диагностику
слоёв raw → normalized → entity → relations. Новые пользовательские функции,
оценки участков и экономические выводы сюда не входят.

## Уже выполнено в рамках корректировки Tasks 1–4

- Geofabrik current PBF сверяется с текущим publisher MD5; stale release
  блокирует pipeline по умолчанию. Явный pinned replay доступен отдельно.
- В отчёт Task 4 попадают Geofabrik checksum status, replication timestamp
  и возраст PBF; для Росстата — опубликованная версия CSV, дата получения и
  возраст публикации в календарных днях.
- Каждая строка ОКТМО валидируется по 13 полям официальной структуры,
  длинам кодовых частей, разделу, обязательному имени и календарному синтаксису
  дат принятия и введения. Эти две даты не задают интервал действия.
  Неизвестная версия структуры блокирует импорт.
- Условия повторного использования Росстата и ссылка на источник сохраняются
  в нормализованном результате и run provenance.
- Failed run сохраняет ссылки на уже полученные raw snapshots, оставляя
  current pointer на последней успешной сборке.
- Content-addressed snapshots остаются раздельными при новых байтах;
  неизменившиеся данные повторно используются без дубликатов.
- Быстрый Docker unit suite запускается для push/PR; крупный live-download
  Geofabrik gate запускается вручную.
- PipelineRun получает идентификатор commit, встроенный в Docker image.

### Task 12 — итоговый quality gate ядра (DONE, 2026-09-28)

Каждый source run публикует проверяемые показатели: полнота схемы,
дубликаты, пропуски обязательных полей, корректность кодов/геометрий,
referential integrity, свежесть, source hashes и commit version. Gate
завершается PASS только при выполнении источниковых порогов; исключения
остаются видимыми в отчёте.

## Очерёдность

Сначала завершить Task 5, затем Tasks 6–8 (модель и целостность), Tasks 9–11
(повторяемость и failure-регрессии), в конце Task 12. Для каждой задачи:
fixture tests → Docker suite → live-check → повторный запуск → evidence.
Если источник устарел или схема неизвестна, результат помечается явно либо
останавливается по порогу источника; тихое принятие данных запрещено.

Этот порядок следует оставшимся пунктам Key Block 01 и ограничивает работу
качеством фактического ядра. Tasks 5–12 завершены; местный и внешний gate
Task 12 прошли с проверенной резервной копией. Девять предупреждений
геометрии OSM остаются видимыми. Сквозная проверка CI и точные показатели
локального запуска: `CORE_QUALITY_GATE_2026-09-28.md`. Порог Task 10 является
явно заданной политикой проекта, а не обещанием частоты публикации источника.
Реестровый коннектор остаётся отдельной задачей Task 13.


## Следующий блок ядра — Task 13

После закрытия Tasks 5–12 выполнить отдельную задачу по официальному
источнику кадастровых участков. Цель: запрос по кадастровому номеру,
неизменяемые снимки, provenance каждого факта и выявление изменений при
сопоставлении повторных ответов. До кодирования подтвердить официальный
машинный интерфейс НСПД/ЕГРН, условия автоматизированного доступа, поля,
лимиты, актуальность и ограничения на персональные данные. Событийную
подписку не считать доступной, пока канал не подтверждён документацией.

Зависимость для Task 5: Geofabrik/OSM может дать дорожные геометрии, однако
в текущем наборе нет геометрии участков. Task 5 сохраняет проверенные
RoadFeature; relation участка с дорогой создаётся только когда появится
подтверждённая геометрия Parcel из официального источника (Task 13). Такая
relation описывает геометрическое соседство/пересечение, не юридический проезд.
