# План повышения качества данных ядра

## Назначение

План усиливает достоверность, свежесть, воспроизводимость и диагностику
слоёв raw → normalized → entity → relations. Новые пользовательские функции,
оценки участков и экономические выводы сюда не входят.

## Уже выполнено в рамках корректировки Tasks 1–4

- Geofabrik current PBF сверяется с текущим publisher MD5; stale release
  блокирует pipeline по умолчанию. Явный pinned replay доступен отдельно.
- В отчёт Task 4 попадают Geofabrik checksum status, replication timestamp
  и возраст PBF; для Росстата — опубликованная версия CSV, дата получения и
  возраст публикации в календарных днях.
- Каждая строка ОКТМО валидируется по 13 полям, длинам кодовых частей,
  control/record type, обязательному имени и календарному синтаксису дат.
  Обратные интервалы отмечаются как source anomalies; целевой субъект с такой
  записью не публикуется, а anomalies вне целевого субъекта видны в отчёте.
- Условия повторного использования Росстата и ссылка на источник сохраняются
  в нормализованном результате и run provenance.
- Failed run сохраняет ссылки на уже полученные raw snapshots, оставляя
  current pointer на последней успешной сборке.
- Content-addressed snapshots остаются раздельными при новых байтах;
  неизменившиеся данные повторно используются без дубликатов.
- Быстрый Docker unit suite запускается для push/PR; крупный live-download
  Geofabrik gate запускается вручную.
- PipelineRun получает идентификатор commit, встроенный в Docker image.

## План оставшихся задач качества

### Task 5 — OSM road features (DONE_WITH_WARNINGS, 2026-09-24)

- Выполнено: 91,455 проверенных highway ways из свежего PBF, CRS/геометрии/IDs
  проверены; 9 GDAL warnings сохранены. Подробности: TASK_05_EVIDENCE.md.
- Извлекать только подтверждённые source features из Geofabrik layers.
- Сохранять OSM type/id/version, source timestamp, tags, geometry и snapshot.
- Проверять валидность геометрии, CRS, пустые/неожиданные типы и counts
  по слоям; сравнивать ограниченную выборку с GDAL read.
- Утверждения о юридическом доступе к участку не выводить из OSM-тегов.

### Task 6 — иерархия ОКТМО субъекта

- Восстановить parent/child связи только из полей официальной схемы.
- Проверять принадлежность к субъекту, полноту уровней, циклы, дубли и orphan.
- Отчёт показывает строки источника, прошедшие каждую проверку, и исключения.

### Task 7 — история и перекодировка ОКТМО

- Использовать интервалы действия, не переписывать ранее сохранённые snapshots.
- Выделять пересечения интервалов и смены кода/названия.
- Сопоставление старого и нового кода хранить как evidence-backed relation,
  отдельно от точного совпадения идентификаторов.

### Task 8 — межслойная схема и целостность

- Закрепить versioned schema rules и fail-closed реакцию на неожиданный формат.
- Проверять foreign keys, endpoint types, source/evidence alignment и
  уникальность natural keys на границах слоёв.
- Не добавлять отношения без подтверждения источника.

### Task 9 — golden snapshots и парсерные регрессии

- Собирать небольшие обезличенные/публичные fixtures, воспроизводящие
  реальные варианты схемы и edge cases.
- Для каждого parser version фиксировать ожидаемые counts, ключи и hashes.
- Любое изменение source schema требует fixture и объяснённого diff.

### Task 10 — свежесть и provenance всех источников

- Сравнивать дату публикации, дату получения и время запуска.
- Выводить stale/unknown/current отдельно от checksum integrity.
- Сохранять точные source URLs, license/use terms, schema version и commit.
- Устанавливать пороги свежести отдельно по источнику и документировать их.

### Task 11 — повторное применение и отказоустойчивость

- Проверять unchanged snapshot replay, changed snapshot replay и rollback.
- Тестировать прерывание загрузки, повреждение файла, ошибку парсера,
  ошибку SQLite и восстановление с последнего успешного run.
- Проверять сохранность предыдущего current pointer и входных evidence.

### Task 12 — итоговый quality gate ядра

Каждый source run публикует проверяемые показатели: полнота схемы,
дубликаты, пропуски обязательных полей, корректность кодов/геометрий,
referential integrity, свежесть, source hashes и commit version. Gate
завершается PASS только при выполнении источниковых порогов; исключения
остаются видимыми в отчёте.

## Очерёдность

Сначала завершить Task 5, затем Tasks 6–8 (модель и целостность), Tasks 9–11
(повторяемость и failure-регрессии), в конце Task 12. Для каждой задачи:
fixture tests → Docker suite → live-check → повторный запуск → evidence.
Если источник устарел или схема неизвестна, результат помечается явно либо
останавливается по порогу источника; тихое принятие данных запрещено.

Этот порядок следует оставшимся пунктам Key Block 01 и ограничивает работу
качеством фактического ядра. Task 5 закрыта с видимыми source warnings;
следующий кодовый этап — Task 6. Перед ним провести раннюю разведку канала
Task 13, чтобы закрепить кадастровый контракт, не начиная реестровый
коннектор до прохождения Tasks 5–12. Task 12 остаётся последним gate после
появления source-specific метрик Tasks 5–11. Для каждой задачи результат принимается
только после fixture tests, полного Docker suite, live-check, повторного
запуска и сохранения run/hash evidence. Task 10 задаёт пороги свежести из
реальной частоты обновления каждого источника; до этого показываем точные
возраста, но не объявляем источник свежим только по факту успешного скачивания.


## Следующий блок ядра — Task 13

После закрытия Tasks 5–12 выполнить отдельную задачу по официальному
источнику кадастровых участков. Цель: запрос по кадастровому номеру,
неизменяемые снимки, provenance каждого факта и выявление изменений при
сопоставлении повторных ответов. До кодирования подтвердить официальный
машинный интерфейс НСПД/ЕГРН, условия автоматизированного доступа, поля,
лимиты, актуальность и ограничения на персональные данные. Событийную
подписку не считать доступной, пока канал не подтверждён документацией.

Зависимость для Task 5: Geofabrik/OSM может дать дорожные геометрии, однако
в текущем наборе нет геометрии участков. Task 5 сохраняет проверенные
RoadFeature; relation участка с дорогой создаётся только когда появится
подтверждённая геометрия Parcel из официального источника (Task 13). Такая
relation описывает геометрическое соседство/пересечение, не юридический проезд.
